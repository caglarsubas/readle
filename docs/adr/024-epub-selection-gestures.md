# 024 — Native EPUB selection gestures

Accepted 2026-11-05 after build-12 owner UAT. Continuous layout must scroll with a native selection active. In Pages, dragging the start/end handle to the text edge and holding must turn the corresponding page while retaining the opposite range boundary. Releasing the handle must stop page turning.

Readium Kotlin 3.1.2's internal `R2BasicWebView.onOverScrolled` returns early whenever `isSelecting` is true. This deliberately prevents a Chromium CSS-column selection bug, but also freezes continuous scrolling. The same guard exists in the later legacy navigator checked during this investigation; a dependency upgrade alone does not supply this behavior.

Readle builds a small local navigator module from the immutable 3.1.2 source commit `71074ea0c424eabbc39a93b48a4cefe366f7741b`. Its source archive is checksum verified. A focused patch lets scrolling use the text's active axis while keeping the paginated-column guard. Native Chromium selection and handles, Readium locators, source files, storage and annotations remain in use.

For pagination, an ActionMode delegate observes the public visibility/lifecycle events Chromium produces during native handle dragging. While a handle is active, it reads the changing DOM range boundaries without constructing or replacing a selection. At a sustained text edge in Pages, it asks Readium’s existing pager to move one viewport. At a top/bottom edge in continuous layout, it scrolls the viewport in bounded steps so the native handle can keep extending the range. A 400 ms dwell and 1 s minimum interval prevent rapid repeated turns. Finishing the native action mode, removing the range, detaching the view or losing the selection cancels the monitor. The opposite selection endpoint is retained. Turns are clamped to the current EPUB spine resource; cross-chapter selection remains open.

The module's build configuration replaces upstream publishing infrastructure, compiles against this app's Android toolchain and retains the same runtime dependency pins. Generated upstream code stays in ignored build output. The Readium BSD license is included in APK assets. See the module README and `patches/readium-selection.patch` for the complete source boundary. No Maven-cache binary modification or reflective access to SDK private fields is used.

Verification uses actual long presses, finger swipes and native handle drags. Continuous scrolling fails in build 12 and passes in build 13 on a Pixel Fold API 36 AVD. All 17 native tests and 3 React Native tests pass; the four native gesture tests also pass on Pixel Fold. Forward selection is saved/reopened and its rendered range checked against the original quote; backward extension retains its end anchor. Post-release pauses verify no continued page turns or scrolling. Physical Z Fold7 / Android 17 UAT remains separate.

References: [Readium's column-selection issue](https://github.com/readium/kotlin-toolkit/issues/325), [pinned source](https://github.com/readium/kotlin-toolkit/tree/71074ea0c424eabbc39a93b48a4cefe366f7741b), [Chromium selection lifecycle](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/public/android/java/src/org/chromium/content/browser/selection/SelectionPopupControllerImpl.java).
